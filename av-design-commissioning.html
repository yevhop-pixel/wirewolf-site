Project context

Define how the room should work

Equipment lists alone do not explain what happens when a user starts a meeting, shares a laptop or combines two rooms. Wirewolf helps review the functional requirements behind the hardware and translate them into a practical control, DSP and commissioning scope.

Scope a complete AV design package or a defined part of an existing project. Responsibilities and deliverables are agreed with the integrator and installation team before work starts. Electrical, structural or other regulated approvals are handled by the relevant project professionals where required.

Technical scope

Design inputs that support installation and testing

Signal flow and equipment scope

Develop system architecture and equipment selections around room requirements and budget. Create source-to-destination signal-flow drawings, inputs and outputs, room modes and equipment interfaces. Identify missing adapters, unclear routing and dependencies that affect programming. Develop or review cable and I/O schedules with consistent device and port names for the installation team to reconcile on site.

Control and user workflows

Define source selection, display power, volume, mute, camera control and room startup or shutdown behaviour. Agree feedback, failure states and operator permissions. The resulting scope gives the programmer and client a shared description of what each room function should do.

DSP design support

Plan microphone, conferencing and playback paths, output zones, gain structure and control points. Review AEC references, mute relationships and routing against the intended room use. Final acoustic checks and tuning require suitable access to the installed room and its actual microphones and loudspeakers.

AV network coordination

Prepare or review AV device addressing, IP and VLAN requirements, Dante routing and NVX distribution plans with customer IT. Document switch-port and endpoint dependencies. IT owns network policy and approves configuration changes, multicast requirements and access arrangements before implementation.

Working together

A commissioning plan built around evidence

  1. Before installation

    Provide room layouts, current drawings, equipment models, user requirements and the project schedule. Identify the designer, IT contact, installer and programming owner. Mark confirmed selections and open decisions so the review can distinguish actionable work from assumptions awaiting approval.

  2. Prepare acceptance checks

    Agree a checklist covering required room modes, source and destination combinations, conferencing audio and video, control feedback and recovery behaviour. Define who witnesses each test, what counts as a pass and what equipment or remote participants the test needs.

  3. After installation

    Collect marked-up drawings, cable labels, confirmed port assignments, firmware versions, source files and configuration backups. Review installation readiness with the site team before booking tests. Record discrepancies between the design and installed system, then agree which revisions are needed and who owns them.

  4. Commission and hand over

    Coordinate functional checks within an approved access and change window. Record results, outstanding defects and retest responsibilities. Deliver the agreed source files, configuration exports, updated technical notes and acceptance record, with recovery information and a walkthrough for the team maintaining the system.

Before we start

Scope and handover questions

Can you join an existing project?
Yes. We can review a defined part of an existing design or support commissioning after installation. Share the latest drawing revision, equipment list, known issues and the responsibilities already assigned to other contractors so the support scope fits the project.
What is included in the handover?
The written proposal identifies the drawings or schedules, source files, configurations and test records to be delivered. Third-party software and modules remain subject to their licence terms. Unresolved items and any tests that could not be completed are recorded explicitly.
