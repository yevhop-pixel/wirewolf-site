Room programming

SIMPL, SIMPL# and SIMPL#Pro work can cover source selection, display power, volume, mute, room modes and shutdown sequences. For 4-Series or VC-4, we review the target environment, required licences and dependencies before confirming compatibility. Existing room standards can guide naming and behaviour across multiple spaces.

Custom device modules

When a device needs custom control, the starting point is its model, protocol documentation and required commands and feedback. The scope defines connection handling, status reporting and test access to the target hardware. Unsupported or undocumented functions require assessment before they become deliverables.

Touch panel design and integration

We design touch-panel page layouts, navigation, graphics and button states, then connect the interface to the room program. The panel shows what is selected, what is muted and what the user can do next. We scope user and technician controls separately, and coordinate DSP, cameras, displays and conferencing workflows with the responsible teams. Integration depends on supported interfaces and the actual equipment configuration.

Integrator support

A defined programming role in your project

Use Wirewolf for a contained module, a room program or an agreed package of development and commissioning support. The integrator retains the client relationship and overall project coordination. We agree who supplies drawings, configures equipment, manages IT access and signs off room operation. Confidentiality and subcontract handover requirements belong in the written scope.

For an existing installation, an initial review establishes what can be edited and tested. Owner authorization, usable source files and compatible tools are prerequisites. A running processor does not establish that editable source can be recovered. If source is missing or unsuitable, replacement development requires a separate scope.

From brief to handover

Make acceptance clear before writing code

  1. Review the inputs

    Provide equipment models, room count, drawings or a signal-flow description, source-file availability and the desired user workflow. Identify firmware or software constraints, the site contact and the requested deadline.

  2. Agree scope and estimate

    We define deliverables, assumptions, exclusions, milestones and acceptance checks in writing. Pricing is a project-specific estimate, with fixed price or time and materials as agreed. Dates depend on confirmed scope and readiness.

  3. Build and verify

    Development includes the agreed logic and interface changes. Testing uses available hardware or an agreed test environment. A room checklist covers normal operation, feedback, reconnection and restart behaviour where included. Unverified items stay visible.

  4. Complete the handover

    The package can include agreed project source files, compiled deliverables, interface assets, dependency notes and test results. Source ownership and delivery are defined in the proposal. Third-party modules and libraries retain their own licence terms.

Remote delivery

Canada and worldwide, with a site partner

Remote programming and commissioning support require authorized access, compatible tools and equipment, an on-site contact and an agreed time zone. The project team arranges approved connectivity and a maintenance window before changes to an operating room.

An on-site technician verifies cabling, power, display behaviour and the physical user experience. Remote feedback alone cannot confirm every room condition. GTA and Ontario site attendance is scoped separately, including travel and the work needed on site.
